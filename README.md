# Product Shots

Turn a product photo into campaign-ready hero shots. One prompt dock drives
every installed model: attach a product photo (or write a prompt only), pick a
surface and a model, and generate. Results stream into the feed and can be
grouped into projects.

The default starting point is `marketing-studio-image` — the Marketing Studio
Image model. Its **preset** setting fetches presets live from
`GET /marketing-studio/image/presets` and, with **Enhance prompt** on, hands the
prompt plus one or two reference images to a preset so composition, lighting and
styling are steered for you (the platform then forces `quality: high`).
Enhance off runs the prompt directly, no reference required. Preset UUIDs are
never hardcoded.

Image and video surfaces carry equal weight — the model picker lists every
installed model for the active surface, with no feature filter and no tier
label, so nothing in the catalog is hidden.

## Requirements

- Node.js 24 (the workspace pins its own toolchain)
- pnpm 11
- A Higgsfield API key from <https://open.higgsfield.ai>

## Setup

```bash
pnpm install
```

Copy the example environment file and point it at the platform:

```bash
cp .env.example .env.local
```

```dotenv
HF_API_BASE_URL=https://api.higgsfield.ai
```

Then start the dev server:

```bash
pnpm dev
```

Open <http://localhost:3000> and use **Connect API key** in the sidebar to paste
the key copied from open.higgsfield.ai. It is stored in an HTTP-only cookie and
only ever used by the server-side generation and upload routes — it is never
exposed to the browser, never written to logs, and never bundled into client
code.

Other checks:

```bash
pnpm typecheck
pnpm lint
pnpm build
```

## How generation works

- `generation/catalog/` holds one file per model. `models.generated.ts` is
  regenerated by the dev server and must not be edited by hand.
- `generation/actions.ts` and `app/api/upload/route.ts` are the only server
  boundaries. They read `HF_API_BASE_URL` and the cookie-held key, then call the
  platform.
- Every submit carries an `Idempotency-Key`, and the dock ignores a second click
  while a submit is in flight, so a double click cannot queue two billable runs.
- Status is polled through the returned status URL until a terminal state, and
  Cancel calls the returned cancel URL rather than just stopping the poll.
- Reference uploads request a signed URL from `app/api/upload/route.ts` and PUT
  the file with no credentials. Signed URLs are never logged.
- History and projects are browser-local (IndexedDB and zustand). Nothing is
  shared between browsers.

## Model catalog notes

The catalog ships 9 image and 30 video models. Five endpoint mappings come from
the platform documentation but have not been confirmed against a live account,
so treat them as unverified until they are exercised:

- `higgsfield-ai/dop/lite`
- `flux-2-pro`
- `blackforestlabs/flux-3/text-to-video`
- the `bytedance/seedance-2.0/fast` prefix
- the `bytedance/seedance-2.0/mini` prefix

Wan 3.0 Prime is wired to the documented `alibaba/wan-3.0-prime/text-to-video`
endpoint only; no image-to-video variant is exposed for it.

No live generation has been run from this checkout, so account-level access and
live response shapes for any model remain unverified.
